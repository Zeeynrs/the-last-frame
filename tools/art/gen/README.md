# tools/art/gen — reproducible art generators (ADR-019)

Every `.pxo` / PNG produced by the design-art agent in TLF-039 and TLF-042 is generated by the scripts in this folder
(Python 3 + Pillow, nothing else). The art is placed pixel by pixel from palette indices (`TLF-CH01-32`), so the
output is deterministic.

| File | Role |
|---|---|
| `lib.py` | palette, `Layer` canvas, deterministic `.pxo` writer (fixed zip timestamps, embedded `data.json` skeleton) |
| `elias.py`, `elias_build.py` | Elias 8-direction sheet (5 authored directions, 3 exact `flip_h` mirrors, 16 tags) |
| `tiles.py` | floor tiles |
| `props.py` | corner pillar, archway N, railing, bench, call box, reset console, lever, clipboard |
| `t2.py` | turnstile, fire shutter, counterweight gear, surge capacitor, pressure switch |
| `t3.py` | route board, security gate, bridge, transit car, dispatch terminal, pocket watch, lever badges, PA horn |
| `ui_wheel.py` | ability wheel (TLF-053, ADR-021): face, bead pointers, 6 segments x 3 states, 16x16 ability icons, lock glyph, the three wheel mockups and the greyscale proof; PNGs go to `assets/ui/ability_wheel/` |
| `step1_statues.py` | Step 1 frozen commuters (`TLF-057`, wishlist §A — 76 assets): 6 base bodies + 4 specific poses (`_idle` & static `_read` 1px outline), 14 prop overlays (`_idle` & `_read`), all 13 pre-assembled commuters (`_idle` & `_read`), 4-frame `24×12` Trace shimmer foot ring, `6×6` overhead clock-hand timestamp glyph |
| `step1_props.py` | Step 1 puzzle & station props (`TLF-057`, wishlist §B — 57 assets): SO-01 selectors/lever/gate, PZ-001 conduit, PZ-006 flap dials/validator/staff door/notice, SO-02 service hatch/bulkhead/floor plates A&B/bell icon, PZ-002 inner shutter, PZ-003 Echo pedestal/card reader/staff barrier/alarm plate, PZ-004 breaker C, PZ-005 standby plate/dead relay C |

| `registry.py` | list of every generated asset (stem, folder, size, layers, frames) |

## Calls (from the repo root)

```
python tools/art/gen/gen_all.py                 # rewrite assets/source/ch01/*.pxo of generated assets
python tools/art/gen/gen_all.py --export        # ... and re-export every runtime PNG with Pixelorama
python tools/art/gen/gen_all.py --sheet         # ... and rewrite the placement sheet + mockups
python tools/art/gen/verify_regen.py            # regenerate in memory/temp, compare with the committed files
python tools/art/gen/verify_regen.py --pixelorama   # also re-export each .pxo in a temp copy and compare PNG bytes
python tools/art/gen/verify_pxo.py --only ch01_ui_ --log design/art/TLF-053_VERIFICATION.txt   # raw Pixelorama log, optional --only filter
python tools/art/check_assets.py                # palette / alpha / size / Elias mirror checks on the PNGs
```

Pixelorama is found via env `TLF_PIXELORAMA` or `D:\Pixelorama\Pixelorama-Windows-64bit\Pixelorama.exe`.
Pixelorama 1.2.3 ignores the `--output` file name and always writes `<name>.png` next to the `.pxo`, so every export
here runs on a temp copy of the `.pxo`. Optional previews write to `$TLF_ART_SCRATCH` (default: system temp).

## What "reproducible" means here

* `.pxo`: **byte for byte** (zip entries carry a fixed date, entry order and JSON key order are fixed).
* Runtime PNG: the committed PNG is the Pixelorama re-export; `verify_regen.py` compares its pixels with the generated
  pixels, and with `--pixelorama` also the exact bytes of a fresh Pixelorama re-export.
* Mockups and the placement sheet: regenerated and compared byte for byte (mockup PNGs fall back to a pixel comparison
  if only the PNG encoder differs). The sheet generator reads only the frozen snapshot below, so it does **not** change when the live room files change.
* **Not covered:** the batch-1 files drawn by Argon in Pixelorama (terrazzo/tactile tiles, subterranean walls,
  `archway_frame_e`, the clock, the palette and the arrival-platform target sheet). They have no generator;
  `verify_regen.py` lists them as *NOT COVERED*. `props.archway_n` and the mockups read some of them as inputs.
* The `.pxo` author field is `TLF design-art agent (Claude Code, Sonnet 5.5)` in generated files; the batch-1 files
  still say Argon.

## Idea for the 9 files marked NOT COVERED (not implemented, nothing changed)
Treat the batch-1 `.pxo` and PNG as **fixed sources**: commit a manifest of their sha256 (for example
`tools/art/gen/fixed_sources.sha256`) and let `verify_regen.py` check the hash instead of regenerating. That turns
"not covered" into "pinned": any accidental edit fails the check, while Argon (or a later agent) can still replace a
file deliberately by updating the manifest in the same commit. A generator is only worth writing for a file when its
look has to change.

## Placement snapshot (TLF-045)
`placement_snapshot_ch01.json` is a **frozen copy of the node positions of the 10 Chapter 1 rooms as they were before the
art integration** (commit `0be1959`, the TLF-042 merge; the commit, its date and the extraction rule are recorded inside
the file). The generators read only this file, never the live room files: TLF-041 replaced the greybox nodes (e.g.
`Clock`) and moved the intercom, so reading the live files crashed `verify_regen.py` with `KeyError: 'Clock'` (ISSUE-036).
The live room files now belong to the integration; the snapshot is not updated when they change.

Deliberate differences between the sheet and the snapshot (they live **only** in the sheet generator, `placement.py`,
never in the snapshot):

| Item | Snapshot (pre-integration) | Sheet / mockups |
|---|---|---|
| `signal_control.intercom` | node at `(352, 160)` in the capacitor lane | sprite on N-wall module `k = 6`, pivot `(528, 154)`; the sheet states that ADR-019 moved the node there |
| Wall clocks (rooms 1, 2, 5, 6, 7) | greybox `Clock` at `(320, 50)` above the apex | pivot = base midpoint of the named N-wall module `+ (0, -38)` (sheet section 0.6) |
| Atrium master clock | `Clock` at `(352, 120)` | kept at the snapshot position, drawn at 2x |
| Everything else | as in the snapshot | as in the snapshot |

To refresh the snapshot deliberately (a new art pass against a newer room layout), rebuild the JSON from the chosen
commit with the extraction rule in its `source.how` field, regenerate the sheet and mockups (`gen_all.py --sheet`), and
commit all of it together.
