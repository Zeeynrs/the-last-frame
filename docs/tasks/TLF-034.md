## Problem 1: interact closes the document and then reopens it (found by tlf-lead, confirmed by the Lead in code)
If the player closes a document's **last page** with `interact`, the same document opens again right away. The same happens when `interact` advances the **last line of a blocking dialogue** while the player stands next to an interactable: the object gets used.

Cause, in a single frame:
1. `DocumentViewer._input` (`scripts/ui/document_viewer.gd:42`) / `DialogueBox._input` (`scripts/ui/dialogue_box.gd:47`) handles the press, closes, and calls `_set_player_blocked(false)`. That calls `player.set_physics_process(true)`.
2. In the same frame, `player._physics_process` → `_handle_interaction` (`scripts/player/player.gd:192`) polls `Input.is_action_just_pressed(&"interact")`. That still returns `true`, because `set_input_as_handled()` only stops event propagation, not `Input` polling. As a result, `request(..., &"use")` is sent to `current_target` again.

The same mechanism applies to every action the player polls (`watch`, `ability_next/prev`, `echo_reset`). For example, `watch` (page back in the viewer) is a problem if a future close path is ever bound to it.

## Requirements
1. **One block/unblock API on the player** instead of three copies of `_set_player_blocked` (DocumentViewer, DialogueBox, JournalScreen):
   - e.g. `player.set_input_blocked(blocked: bool)`
   - on unblock, record `Engine.get_physics_frames()` and ignore every `is_action_just_pressed` in `_handle_interaction` for that physics frame (and the next one, if a press can arrive across two steps; justify your choice)
   - the three UIs call this API
   - the fallback lookup chain (session → group → find_child) lives in **one** place
2. Alternative (allowed if you justify it): event-based interaction via `_unhandled_input`, so handled events never reach the player. Mind determinism: the interaction request must still land in the SimClock order (ADR-003). If unsure, use option 1.
3. Behaviour must not change otherwise: the next deliberate `interact` press after closing works normally (no "lost" input).
