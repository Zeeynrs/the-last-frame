# Task: TLF-074 — view_mode plumbing and the side-view movement/camera rule (ADR-025)

**Owner:** Opus · **Reviewer:** Lead · **Priority:** P1 · **Status:** BLOCKED until TLF-072 (960 x 540) is merged

## Goal
Rooms declare a view mode; `Player`, `RoomCamera`, `DepthSort` and the HUD follow it. Only `iso` and `side` are implemented. `topdown` is only a reserved value.

## Requirements
1. `metadata/view_mode` (StringName, default `&"iso"`) read by `RoomRouter`; signal `view_mode_changed(mode: StringName)` on room entry; `RoomRouter.current_view_mode() -> StringName`.
2. `Player`: in `side` mode only `move_left` / `move_right` move Elias (vertical input ignored), speed `walk_speed`, facing `e` or `w`; a separate `SpriteFrames` per mode, swapped on `view_mode_changed` (`iso` keeps `elias_sprite_frames.tres`; `side` loads `elias_side_sprite_frames.tres` once Argon delivers it, with a placeholder (mirrored `idle_e` from the iso `e` pose) so the tests do not wait for the art).
3. `RoomCamera`: a horizontal-only mode for `side` rooms wider than the screen (whole-pixel steps, clamp to the scene bounds); a side room that fits the screen has a fixed camera. `DepthSort` is skipped in `side`.
4. Echo and Rewind: positions recorded in `side` stay on the floor line; Freeze and Trace work on side-view targets; refused abilities use an existing reason key.
5. Save/load: the saved room id decides the mode; loading in a `side` room restores mode, sprites and camera together.
6. Tests: mode switch both ways without leaks, side movement and facing, camera fixed/horizontal clamp, each ability once in a test `side` room (a fixture scene), Echo/Rewind positions on the floor line, save/load in the fixture. The existing tests stay green. Full validate 0 failed, no SCRIPT ERROR.

## Out of scope
The pilot scene, art, `topdown`, puzzles.
