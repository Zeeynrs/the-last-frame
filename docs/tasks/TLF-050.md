# Task: TLF-050 — Step 1 foundations: `TraceMemory` + progressive ability unlocks (save)

**Owner:** Opus implementation agent (`wt-opus-core`, branch `agent/opus-core`) · **Status:** READY (after TLF-049) · **Priority:** P0 (ADR-020 Step 1; Trace does nothing visible today) · **Dependencies:** ADR-020 amendment "TLF-047 phase 1 approved", `design/ch01/CH01_EXPANSION.md` §0.1, §0.3, §4a, §8.4

## Why
- Nothing listens to `Interactable.traced`, and `_on_traced()` is empty (`interactable.gd:126/153`), so Trace shows nothing in the game.
- Trace becomes the starting ability and the "information ability" of the expansion.
- Unlocks: `PocketWatch.unlocked_abilities` exists (default all four) but isn't saved and has no unlock events.

These are the foundations every Step 1 spec builds on. The exact puzzle contents follow in TLF-047 phase 2. Build the mechanisms generically; content comes later as data.

## Requirements
1. **`TraceMemory`** (new class, `extends Interactable`, `traceable = true`; e.g. `scripts/narrative/trace_memory.gd`), with exports:
   - `lines: Array` (`[speaker_key, text_key]` pairs)
   - `flag_id: StringName` (set on the first trace)
   - `journal_key` + `journal_category` (default `observation`)
   - `one_shot_dialogue: bool`
   - `_on_traced`:
     - plays the lines **non-blocking** via the existing `DialogueBox.play_sequence` (sequence ID `trace.<object_id>`)
     - sets the flag
     - adds the journal entry **once**
     - emits a signal `memory_revealed(object_id)`
   - Tracing again replays the lines (no new journal/flag).
   - `use` → `unsupported` (Trace only), unless an export allows `use`.
   - No change to `interactable.gd`. If `_on_traced` isn't enough as a hook: stop and report.
2. **Ability unlocks:**
   - `AbilityUnlocks` (session-scoped or in `NarrativeState`; justify it), API:
     - `unlock(ability)`, `is_unlocked(ability)`, `unlocked() -> Array`
     - signal `ability_unlocked(ability)`
   - `PocketWatch` reads it (`unlocked_abilities` follows it; the selected ability falls back if locked).
   - `InteractionService` stays unchanged. A locked ability is filtered by the pocket watch (feedback reason `&"ability_locked"` + UI text key appended to `ui_feedback.csv`).
   - Unlock triggers as data: a node `AbilityUnlockTrigger` (fires on a flag / on `ProgressionPickup` / on puzzle SOLVED), configurable via exports.
   - Chapter start: unlocked = `[trace]` **only** when the chapter config says so (export on Chapter01/ChapterRoot). Default for tests and the old flow: all four, so existing playthroughs stay green until Step 1 is built.
3. **Save:**
   - schema bump (v3) with `unlocked_abilities`
   - migration v2→v3: **all four unlocked** (old saves stay playable)
   - restore sets the watch.

  - `TraceMemory` with **real input** (select Trace, press `watch` on the object): line shown, flag set, journal entry once; repeat → no second entry
