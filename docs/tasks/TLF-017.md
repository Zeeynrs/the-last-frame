## Requirements
- `Settings` (autoload, `extends Node`):
  - typed properties with defaults:
    - `master_volume`, `music_volume`, `ambience_volume`, `sfx_volume`, `voice_volume` (0.0–1.0)
    - `text_scale` (1.0, allowed 0.75–2.0)
    - `subtitles_enabled` (true)
    - `reduced_effects` (false)
    - `assist_extended_timing` (false)
    - `screen_shake` (1.0)
  - `load_settings()` on `_ready`, `save_settings()`, `reset_to_defaults()`
  - `setting_changed(key, value)` signal
  - applies volumes to buses in dB (linear 0 = mute)
  - clamps out-of-range values; an unknown or corrupt file produces defaults and a warning, never a crash
  - `get_timing_window(base_ticks: int) -> int`: returns `ceil(base * 5/3)` when `assist_extended_timing` is on, else `base` (180 → 300). Puzzles will call this.
- Remapping API:
  - `remap_action(action, slot, event) -> StringName` (`&""` on success, or `&"conflict"` / `&"unknown_action"` / `&"invalid_event"`)
    - slot is `&"keyboard"` or `&"joypad"`
    - a conflict means the event is already bound to another **gameplay** action (use the same rules as `test_no_input_binding_conflicts`; the allow-list stays `interact`/`confirm`)
  - `reset_action(action)`, `reset_all_bindings()`
  - overrides persist in the settings file and are re-applied on load; joypad events stay device −1
- `echo_reset` action: R (physical) + joypad button 3, device −1. Add it to the gameplay action lists in the binding tests.
