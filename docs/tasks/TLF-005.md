- [ ] **Room table**, one row per room:
  - ID, beat, purpose
  - footprint in tiles (W×H, 32×16 iso); each room must fit the 640×360 view or state its camera behavior (fixed/scroll)
  - doorways (`door_id`, wall side, tile position)
  - puzzle(s), checkpoint (yes/no), safe anchors
- [ ] **Doorway graph:** every static edge in Ch1 (`room:door ↔ room:door`) plus the PZ-005 dynamic edges (reference only, no redefinition). Every doorway is paired exactly once; non-traversable edges are flagged.
- [ ] **Critical path:** the ordered route from `ch01.arrival_platform` to `ch01.street_exit`, with which puzzle gates each step. Also optional routes/backtracking, and a check that no one-way transition can strand the player.
- [ ] **Placement constraints for puzzles:** for every ability target in PZ-001…005, the intended standing spot and confirmation that supported targets sit within 96 px of it. Note where nearest-target ambiguity could occur and how the layout avoids it (e.g. the PZ-001 pillar placed so Rewind auto-targets the gate, while the pillar can still be reached deliberately to teach `unsupported`).
- [ ] **Checkpoints/saves:** where they sit (at least one per puzzle room entrance) and what state they capture (ID references only).
- [ ] **Modular kit list:** the shared tiles and props each room reuses vs. unique set pieces, so TLF-010 can scope the art.
- [ ] Section "Deltas" (changes needed in the beat sheet/specs, or "none") and "Open questions".
