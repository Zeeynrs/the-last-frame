# Task: TLF-035 — `validate.ps1` fails on leaks at exit

**Owner:** Opus implementation agent (`wt-opus-core`, branch `agent/opus-core`) · **Status:** READY · **Priority:** P2 (hardening the quality gate) · **Dependencies:** TLF-028 (merged), `main` at `3df2583`

## Why
"No leaks" is part of every merge review (TLF-019, TLF-031, RISK-018 …), but nothing checks it automatically. The Lead and tlf-lead read the raw output by hand. Step 3 of `tools/validate.ps1` (lines 114–121) only checks the test runner's exit code. It deliberately ignores `ERROR:` lines, because negative tests log expected errors. As a result, a leak at exit goes unnoticed in Flash's and Opus's handoffs.

## Requirements
- Step 3 (test runner) and step 2 (script check) fail if Godot's output contains a leak message at exit. At least these:
  - `ObjectDB instances leaked at exit`
  - `resources still in use at exit`
  - `RID allocations of type ... were leaked at exit` / `... RID ... leaked`
  - `Orphan StringName` (only if it actually appears in 4.7.2; verify it, don't guess)
- Match on the message text, not on the `WARNING:`/`ERROR:` prefix, so expected `ERROR:` lines from negative tests don't trigger a failure.
- On failure: `VALIDATION FAILED: <step> leaked at exit:` followed by the matching lines, exit code ≠ 0.
- On success, an explicit line such as `Leak check: clean` per step, so handoffs show the check ran.
- Optional, if cheap: the test runner calls `--verbose` only on failure, or the script prints a hint to rerun with `--verbose`.

## Allowed files
`tools/validate.ps1`, `tools/validate_selftest/**` (new; for fixtures). No docs (the Lead updates them).

## Acceptance criteria
- [ ] Fresh clone: `tools/validate.ps1` passes on current `main` with `Leak check: clean` (raw output in the handoff).
- [ ] Proof the check bites (mutation check, don't commit it): a throwaway test that deliberately leaves a `Node` without `free()` makes validate red with the leak line in the output. Put the raw output in the handoff. Also show red for `resources still in use`, if that can be reproduced cheaply.
- [ ] Expected `ERROR:` lines from the existing negative tests still don't cause a failure.
- [ ] Still runs on Windows PowerShell 5.1 (TLF-028 constraints: cmd.exe wrapper, no NativeCommandError).

## Stop conditions
Stop and report if `main` currently leaks (then that's a separate bug with an owner first), or if leak messages in 4.7.2 can't be reliably separated from expected test errors.
