# Task: TLF-036 — Headless runs never touch the real save and settings files

**Owner:** Opus implementation agent (`wt-opus-core`, branch `agent/opus-core`) · **Status:** READY (after TLF-035) · **Priority:** P1 (data loss on dev machines) · **Dependencies:** `main` at `813b2c8`
**Decision:** ADR-011 amendment 2026-10-31 (ISSUE-026, TLF-036). Read it first.

## Why (ISSUE-026)
On 2026-10-31, Flash's ad-hoc headless probes (`--path .` in `tlf-implementation-qa`, project "The Last Frame") wrote `user://saves/slot_0.json` into the real save folder `app_userdata/The Last Frame/saves`. tlf-lead removed it with the user's OK. That's the third time (ISSUE-016 test, ISSUE-022 Lead probe, ISSUE-026 Flash probe). The "always set a test save root" rule is not enough on its own, so the guard goes into the code.

## Requirements
1. `SaveStore` (`scripts/save/save_service.gd`): the default root is resolved at runtime:
   - `user://headless/saves` when `DisplayServer.get_name() == "headless"`
   - otherwise `user://saves`
   - Override: env var `TLF_ALLOW_REAL_USER_DATA=1` → always `user://saves`.
   - An explicitly assigned `save_root` still wins (existing tests set their own roots; don't change them).
   - Check in 4.7.2 that `DisplayServer.get_name()` really returns `"headless"` under `--headless` and under `-s`. Don't guess; put the probe output in the handoff.
2. `Settings` (`scripts/settings/settings.gd`): the same rule for `settings_path` → `user://headless/settings.cfg`. Remap and settings tests must never write the real `user://settings.cfg`.
3. Read the resolution once, at `_init` / when the autoload starts. Keep a public, testable function, e.g. `static func resolve_default_root(display_name: String, env_override: String) -> String`, so tests don't depend on the real environment.
4. Make the real root visible in logs: one `print` at startup in headless mode (`SaveStore: headless, root = ...`), so handoffs show it.

## Allowed files
`scripts/save/save_service.gd`, `scripts/settings/settings.gd`, `tests/save/**`, `tests/settings/**`, `tools/validate.ps1` (only if TLF-035 isn't merged yet: coordinate with yourself, keep it to one commit per task).

## Forbidden files
Everything else. Don't change the existing tests' `TEST_SAVE_ROOT` assignments; they stay as an extra safety layer.

## Acceptance criteria
- [ ] `tools/validate.ps1` passes on a fresh clone (raw output).
- [ ] Unit tests for `resolve_default_root` / the settings equivalent: headless → headless path; non-headless → real path; env override → real path; an explicit assignment wins.
- [ ] **Real-folder proof:** before and after a full `validate.ps1` run, plus one ad-hoc probe that loads `Chapter01.tscn` headless **without** setting a save root, list `%APPDATA%\Godot\app_userdata\The Last Frame\saves\` and `settings.cfg` (names, sizes, timestamps). Nothing may change. The probe's autosave must land in `user://headless/saves`.
- [ ] Never delete anything in the real folder. If it isn't empty when you start, leave it alone and note what's there in the handoff.

## Stop conditions
Stop and report if `DisplayServer.get_name()` doesn't reliably detect headless in 4.7.2 (then the Lead decides between a command-line flag and an env var), or if the guard would change behaviour in the editor (F5/F6).
