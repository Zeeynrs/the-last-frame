## Problem A: the checkpoint becomes the target (found by tlf-lead in a windowed probe, root cause confirmed by the Lead)
At game start, `PocketWatch.current_target` **and** `player.current_target` both point to `ch01.arrival_platform.checkpoint` (`CheckpointZone` → `TriggerZone` → `Interactable`, at the spawn (352,160)). The real pickup `global.pocket_watch` at (368,168) loses because the checkpoint is closer. Effects:
- The cyan `AbilityMarker` sits above Elias (347,127). TLF-038 only fixed the coordinates.
- E at the start "uses" the checkpoint → "Nothing happens.".
- The same applies wherever a `TriggerZone`/`CheckpointZone` sits within reach.

Causes:
- `scripts/player/pocket_watch.gd:150`: `var pool = supporting if not supporting.is_empty() else in_range`. If no object supports the selected ability, **every** interactable in range is a candidate, including triggers.
- `scripts/player/player.gd::choose_best_interactable` (and the candidate list from the `InteractionDetector`) doesn't filter at all.

### Requirements A
- Define "targetable" through the existing API, **without** changing `interactable.gd` or `trigger_zone.gd` (shared contract / Opus):
  - `can_interact(actor, &"use") != &"unsupported"` **or**
  - `supports_ability(a)` for at least one `a` in `Interactable.WATCH_ABILITIES`.
  - A blocked but supported `use` (e.g. `unpowered`, `jammed`, `already_open`) **stays** targetable, so its feedback still appears.
- `choose_best_interactable` and `choose_watch_target` consider only targetable objects. The fallback pool in `choose_watch_target` = targetable objects in range (so "The pocket watch cannot affect this object." still appears on e.g. a usable pickup), never triggers/checkpoints.
- The ADR-006 order (nearest, tie → smallest `object_id`) stays the same.
- Echo selection (`echo` → `null`) stays the same.

## Problem B: UI theme fails silently (tlf-lead note A on TLF-040)
`UITheme._setup_theme()` (`scripts/ui/ui_theme.gd`) returns **completely** if `DirAccess` doesn't find `res://.godot/imported/tlf_pixel_mono.ttf-*.fontdata`. Then not only the font but also every stylebox, colour and font size is missing, with no message. It's untested in an exported build (PCK).

### Requirements B
- Styles, colours and sizes are **always** set up; only the font depends on availability.
- Check the font via `ResourceLoader.exists(FONT_PATH)` / `load()` instead of listing `.godot/imported`. Keep the `--import` order problem from TLF-040 solved (e.g. in `Engine.is_editor_hint()`/import mode, defer quietly without an error; at game runtime set it, and if it's missing, `push_warning("UITheme: TLF Pixel Mono not available, using default font")` exactly once).
- `ensure_initialized()` sets the font up later if it was missing at `_init` (today it only does this when `default_font == null`; keep that working).
