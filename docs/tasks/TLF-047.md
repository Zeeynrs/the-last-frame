# Task: TLF-047 — Chapter 1 expansion design (phase 1: concept doc → Lead/user approval)

**Owner:** Design agent: Claude Code (Sonnet 5.5), worktree `tlf-design-art`, branch `adityadaffa522/tlf-art-batch2` (`git pull origin main` first). Standing in for Argon as puzzle/narrative designer for this task.
**Status:** READY · **Priority:** P0 (playtest #2: "chapter feels very short") · **Decision:** ADR-020 (read first)

## Why
In playtest #2 the user had no bugs and loved the two-ability combos ("a perfect mechanic"), but found Chapter 1 much too short. The target is 30–45 min (beat sheet: 38). We deepen the combo core instead of padding it.

## Read before designing (mechanics are fixed; the code is authoritative)
- `design/ch01/CH01_BEAT_SHEET.md`, `design/ch01/ROOM_GRAPH.md`, `design/ch01/puzzles/CH1-PZ-001..005.md` (format, given/when/then tests)
- `scripts/puzzle/objects/*.gd`, `scripts/temporal/temporal_component.gd`, `scripts/echo/echo_service.gd`, `scripts/spatial/*`: what Rewind / Freeze / Trace / Echo (1 echo, 1200-tick cap, occupancy) / doorway reassignment / Fast-Forward actually do. **Reuse existing object classes** where possible (new behaviour costs implementation time).
- ADR-015 (reach 36 px / watch 96 px), ADR-016 (SOLVED latch), ADR-019 (frozen collision), SD-1 (scope), RISK-018/ISSUE-021 (how a puzzle was accidentally solvable without its ability).

## Phase 1 deliverable: `design/ch01/CH01_EXPANSION.md` (concepts, not full specs)
1. **Time budget:** a table of the current beats (estimate) vs. the target; where the new minutes come from. Use tlf-lead's figure for the user's actual playtime when it's available (ask the user via tlf-lead if it's missing; don't guess).
2. **≥ 5 concepts for the main path** (3 will be chosen), each with:
   - name, room (existing or new), the **ability combo** and why it's new in this chapter
   - core idea in 3–5 sentences, the "aha" moment, the failure path and its feedback
   - which existing classes it reuses, which new behaviour it needs
   - **why it can't be solved without the combo** (the RISK-018 lesson: name the shortcut risks and how geometry/timing excludes them)
   - estimated minutes for a first-time player
3. **≥ 4 concepts for optional side puzzles** (3 will be chosen): same format, plus the reward (Memory Fragment ID `ch01.fragment.<name>` + readable) and how a player finds them (no forced backtracking).
4. **At most 2 second stages** for PZ-001..005, only with a new combo.
5. **Placement sketch:** which room, which tile area. New rooms (max 2) with footprint + graph edges. The order on the main path, and where Fast-Forward appears, if anywhere (at most once, late).
6. **Narrative tie-in:** which of the new readables/fragments deepen Operator / Mira / ELYSIUM / 23:59 (no new main revelation; Beat 09 stays the only one).
7. **Open questions** for the Lead/user.

**Stop after phase 1** and report. Phase 2 (full specs CH1-PZ-006..008 / CH1-SP-01..03 in the existing spec format with given/when/then tests, beat sheet + ROOM_GRAPH revision, text in `CH01_TEXT.md`) is released by the Lead after approval.

## Acceptance criteria (phase 1)
- [ ] All the points above are in the concept doc. Each concept has the combo, the shortcut analysis and a minute estimate.
- [ ] The sum of the chosen proposal (3 main + 3 optional + at most 2 stages) reaches ≥ 25 min main path and ≥ 8 min optional, calibrated against the measured/reported actual time.
- [ ] No new mechanic outside SD-1 (+ FF at most once); no timing precision beyond the assist window; no padding.

## Stop conditions
Stop and report if a concept needs a new mechanic or a change to an existing contract (InteractionService, TemporalComponent, EchoService), or if the target can't be reached without padding.
