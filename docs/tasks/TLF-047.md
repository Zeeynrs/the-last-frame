# Task: TLF-047 — Chapter 1 expansion design (phase 1: concept doc → Lead/user approval)

**Owner:** Design agent: Claude Code (Sonnet 5.5), worktree `tlf-design-art`, branch `adityadaffa522/tlf-art-batch2` (`git pull origin main` first). Standing in for Argon as puzzle/narrative designer for this task.
**Status:** READY · **Priority:** P0 (playtest #2: "chapter feels very short") · **Decision:** ADR-020 **including both 2026-11-01 amendments** (read first)

## Why
In playtest #2 the user had no bugs and loved the two-ability combos ("a perfect mechanic"), but found Chapter 1 much too short. The target is 30–45 min (beat sheet: 38). We deepen the combo core instead of padding it.

**The user's direction** (after playtest #2, verbatim in spirit):
- develop the story
- start with **only one ability**
- make the world building and environment more interesting
- add **NPCs** around
- add more puzzles

The amendment to ADR-020 turns this into rules: progressive unlock, frozen commuters as NPCs (plus at most 1–2 interactive ones), a "story of the room" per room, and sub-beats around the 10 core beats.

## Phase 1 deliverable: `design/ch01/CH01_EXPANSION.md` (concepts, not full specs)
1. **Time budget, measured:** the user finished all of Chapter 1 in **under 5 minutes** (estimate 38). Each existing puzzle took well under a minute.
   - Table: current beats (estimate vs. realistic actual) → target for the next playtest **≥ 15 min** first-time (vertical-slice goal stays 30–45).
   - Explain where the minutes come from. **Depth per puzzle** is the main lever:
     - ≥ 3 dependent steps
     - information the player has to discover first (Trace, readables, NPC memories, partly from another room)
     - plausible wrong options
     - small hubs with 2–3 sub-goals in any order
   - Count alone isn't enough.
2. **≥ 5 concepts for the main path** (3 will be chosen), each with:
   - name, room (existing or new), the **ability combo** and why it's new in this chapter
   - core idea in 3–5 sentences, the "aha" moment, the failure path and its feedback
   - which existing classes it reuses, which new behaviour it needs
   - **why it can't be solved without the combo** (the RISK-018 lesson: name the shortcut risks and how geometry/timing excludes them)
   - estimated minutes for a first-time player (**main combo puzzles ≥ 3 min, solo ability puzzles ≥ 1.5 min**; justify it by the number of steps / discovery, not by a feeling)
3. **≥ 4 concepts for optional side puzzles** (3 will be chosen): same format, plus the reward (Memory Fragment ID `ch01.fragment.<name>` + readable) and how a player finds them (no forced backtracking).
4. **Deepening PZ-001..005:** for each existing puzzle, a proposal for how it gets more steps / discovery (second stage, more objects, a clue from another room), still with combos and without padding. Each with a realistic minute estimate.
4a. **Ability curve:**
   - Which ability the watch starts with, and why. The order of the unlocks, each tied to a story moment (what happens, where, who/what triggers it).
   - For each new ability, a short **solo puzzle** (alone, before combinations).
   - Then the re-sequenced order of all puzzles (old and new) as a table: room · puzzle · abilities available · abilities required · minutes.
   - Check for every existing PZ-001..005 that it stays solvable at its new position. PZ-001 today needs Trace+Rewind: what changes?
4b. **NPCs:**
   - ≥ 8 frozen commuters across the rooms. For each: who they are, what they were doing at 23:59, their Trace memory (1–2 lines), and their link to a puzzle/fragment/readable if any.
   - Optionally 1–2 interactive NPCs: concept, lore fit (evacuation 23:54, lock 23:59, Operator only a voice), what they reveal and what they deliberately **don't** reveal (Beat 09 stays the only revelation).
4c. **World building per room:**
   - "Story of the room" (2–4 sentences: what happened here between 23:54 and 23:59).
   - Dressing/signage/light mood, as a wish list for design-art (only what serves the story).
   - New readables.
4d. **Story sub-beats:** revision sketch of the beat sheet (the 10 core beats stay; new sub-beats in between), with minutes.
5. **Placement sketch:** which room, which tile area. New rooms (max 2) with footprint + graph edges. The order on the main path, and where Fast-Forward appears, if anywhere (at most once, late).
6. **Narrative tie-in:** which of the new readables/fragments deepen Operator / Mira / ELYSIUM / 23:59 (no new main revelation; Beat 09 stays the only one).
7. **Open questions** for the Lead/user.

**Stop after phase 1** and report. Phase 2 (full specs CH1-PZ-006..008 / CH1-SP-01..03 in the existing spec format with given/when/then tests, beat sheet + ROOM_GRAPH revision, text in `CH01_TEXT.md`) is released by the Lead after approval.

## Acceptance criteria (phase 1)
- [ ] All the points above are in the concept doc. Each concept has the combo, the shortcut analysis and a minute estimate.
- [ ] The sum of the chosen proposal (3 main + 3 optional + at most 2 stages + solo puzzles of the ability curve + NPC/story sub-beats) reaches **≥ 15 min first-time on the main path** (next-playtest target) plus optional content, calibrated against the measured < 5 min. Lay out a path to 30–45 min as a second step.
- [ ] Ability curve, NPC list, story of the room for all rooms and sub-beat sketch are present. The concept doc ends with a short **summary for the user** (in plain language; the user decides on story and NPCs).
- [ ] No new mechanic outside SD-1 (+ FF at most once); no timing precision beyond the assist window; no padding.

## Stop conditions
Stop and report if a concept needs a new mechanic or a change to an existing contract (InteractionService, TemporalComponent, EchoService), or if the target can't be reached without padding.
