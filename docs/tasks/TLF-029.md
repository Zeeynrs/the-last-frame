# Task: TLF-029 — Frame-stepping tests (real input + physics) in the test runner

**Owner:** Opus implementation agent (`wt-opus-core`, branch `agent/opus-core`) · **Status:** READY after TLF-028 · **Priority:** P1

## Problem
`tests/run_tests.gd` runs every test synchronously inside one `_process` frame (ADR-012 am.). A test can't wait for physics frames, so "playthrough with real input + physics" (TLF-009 acceptance) is impossible as a test. Today it is only proven by Lead runtime probes, which aren't repeatable in CI.

## Objective
Tests can `await` frames: a test method that returns a coroutine is awaited by the runner. Helpers advance physics frames with real input, so a Chapter01 playthrough can run as a normal test.

## Allowed files
- `tests/run_tests.gd`, `tests/support/base_test.gd` (helpers: `await physics_frames(n)`, `press(action)`/`release(action)`, `await until(cond, max_frames)`)
- `tests/support/test_test_runner_async.gd` (self-tests of the runner)
- `tests/chapters/ch01/test_ch01_real_playthrough.gd` (new) **only after Flash's TLF-009 is merged**

## Requirements
- Sync tests keep working unchanged (all existing tests pass with no edits).
- An awaited test that never finishes fails after a timeout (default 3600 frames) with a clear message. The runner still prints the summary and quits with the failure count.
- Input actions pressed by a test are released afterwards, even on failure. No state leaks between tests.
- Tests that use Chapter01 point SaveService at a test folder and clean it up (ISSUE-016).

## Acceptance criteria
- [ ] All existing tests pass unchanged. `tools/validate.ps1` exits 0.
- [ ] Runner self-tests: an async pass, an async failure, an async timeout, input released after a failing async test.
- [ ] After TLF-009 merges: a real-input playthrough test reproduces the Lead probe (arrival → concourse → Rewind via pocket watch → bay; PZ-001 SOLVED; autosave written to the **test** save folder), then continues through PZ-002 (Rewind + Freeze via watch) and PZ-003 (Echo via watch) to the waiting lounge.

## Stop conditions
Stop and report if awaiting inside the runner can't be made reliable in headless 4.7.2, or a forbidden file is needed.
