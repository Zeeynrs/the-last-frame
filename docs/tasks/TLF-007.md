## Requirements
- **SimClock:** `tick: int` increments once per `_physics_process` while not paused. It exposes `step(n)` for tests. No gameplay code may read `Time.get_ticks_*`.
- **IdRegistry:** `register(id, node)` / `unregister` / `resolve(id) -> Node`. It rejects (`push_error` and returns false) any empty ID, an ID failing the ADR-005 regex, or a duplicate. Every Interactable registers on `_ready` and unregisters on `_exit_tree`.
- **InteractionService:** exactly the ADR-006 signatures. Order of operations:
  1. resolve the target; if missing → `&"missing_target"`
  2. call `can_interact`; non-empty reason → return it, with no state change
  3. if `progression` is true and the actor ID starts with `echo.` → `&"echo_forbidden"`
  4. call `interact`
  5. emit `interaction_applied` with the current tick
- **Player:**
  - `CharacterBody2D`, 8-direction screen-relative movement
  - diagonals follow the 2:1 isometric axes (`Vector2(2, 1).normalized()` family), so walking along tile edges looks right
  - `@export` walk speed (px/s at 640×360)
  - stick deadzone from the input map
  - movement happens in `_physics_process`
- **Interaction targeting:** candidates are Interactables inside an `Area2D` radius. Pick the closest by distance; ties go to the lexicographically smallest `object_id` (deterministic). Show a prompt Label above the current target. `interact` sends `request(&"player", target_id, &"use")`.
- **TestRoom:**
  - a 2:1 isometric greybox floor of 32×16 tiles, at least 10×10 (ADR-003), with walls/collision on the edges and one obstacle
  - two Levers close together, for the tie-break check
  - Y-sort enabled
